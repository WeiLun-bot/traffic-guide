# 第一場簡報：三年成果與模組化整體架構

從四場簡報總覽選第一場，或在本機預覽網址後加 `#results-intro`。試作情境可從「05 一般道路情境 → G1-01」開啟，網址為 `#results-scenario-g1-01`。

全場共 70 頁，包含一般與複雜道路情境各 18 個。一般 18 個情境皆有「現況議題 → 佈設成果」兩頁；複雜 18 個情境皆有現況議題，其中 C2-02 平行匝道型交流道依使用者指示複用 C4-04 迴轉道的現況圖、照片與說明。全部情境皆在第一場的播放順序與目錄內，不需切到第三、第四場才能逐一介紹。

情境頁首保留編號、情境名稱與道路概況，移除提問式副標題及「全部情境／現況議題／佈設成果」頁內按鈕列，圖片與說明向上使用剩餘高度。使用頁尾前後頁切換，或由頂部「05 一般道路情境／06 複雜道路情境」回到完整列表。

章節目錄中，一般與複雜情境的第一個按鈕顯示「編號＋情境名稱＋現況議題」，例如 `G1-01 無號誌市區正交三岔路口現況議題`；佈設成果按鈕維持 `G1-01 佈設成果`。頁尾切頁文字、頁面 ID 與播放順序維持原設定。

「05 一般道路情境」以 18 張佈設圖縮圖一次總覽，桌面採 6 欄、3 列，卡片保留情境編號與完整名稱。省略標題下的操作說明，名稱下方不預留空白行，讓縮圖使用更多高度。縮圖直接使用各情境「佈設成果」頁的同一張圖及初始畫面設定，包含已儲存的縮放、上下左右位置與旋轉；沒有設定時顯示原始畫面。臨時拖曳或縮放不影響總覽，須套用為初始畫面才會同步。點選卡片進入該情境的現況議題，再按下一頁看佈設成果；平板、手機分別改為 3 欄、2 欄，可向下瀏覽。

點「編輯內容」後，情境現況右欄提供「＋新增現況議題」，成果頁提供「＋新增佈設說明」。每項標題、內文可直接編輯，旁邊的 ↑、↓、刪除可調整清單；編號自動更新，支援復原／重做。按既有「儲存」寫回設定檔；資料存在 `content.results[pageId].points`，保留舊文字設定與獨立情境 ID。即使刪除全部項目，重新載入也不會補回原清單。預覽隱藏編輯工具，說明過多時在右欄內捲動，圖片與頁尾維持一頁高度。

## G1-01 試作

- 現況議題：現況圖與照片，搭配停讓提示、路側混用、左轉與直行三個問題。
- 佈設成果：完整改善圖，搭配空間邊界、行人穿越、直轉動線與環境提示四項重點。
- 兩頁都可開啟原圖、縮放與拖曳；「設定初始畫面」沿用旋轉、縮放與位置功能。視角以第一場自己的頁面 ID 保存。
- 文字可透過「編輯內容」修改，沿用共用 JSON、復原／重做與儲存流程。更換共用素材時，引用同一素材的頁面也會更新。
- 播放順序：G1-01 現況 → G1-01 佈設成果 → G1-02 現況 → G1-02 佈設成果，依序完成 18 個一般情境後進入複雜情境。第一場聚焦整體成果；第三、第四場維持深入解說。

## 一般道路情境的佈設成果

每個一般情境的第二頁沿用 G1-01 的呈現：左側完整佈設圖，右側 3～4 點簡短說明及相關模組編號。由各情境 Typst 的「交通設施設置建議與整體設置圖例」及必要的圖例解說整理，採對外簡報用語，不顯示來源註解或提問副標題。

新補 17 頁的資料集中於 `data/results/general-strategies.json`，保存完整 SVG 路徑、尺寸、SHA-256、情境編號及解說來源。G1-01 原頁面、素材 ID 與說明 ID 保留，既有編輯設定繼續有效。新增頁面 ID 統一為 `results-scenario-g1-02-strategy` 等。

圖檔直接引用 `materials/04-一般道路情境/G1-02/` 等資料夾的原始 SVG，不轉檔或改寫。16 個情境採 `情境編號_…交通設施整體設置圖例.svg`；G1-02 採 Typst 明確引用的 `G1-02_無號誌鄉區正交三叉路口-高雄甲典街.svg`。G4-01 資料夾內另一張 G4-02 圖不混用，G4-02 使用其自身資料夾的圖。

可執行 `py tools/prepare-results-strategies.py <原始 chapters/04-general-scenarios 路徑>` 更新原圖尺寸及來源校驗碼；保留已整理的簡報文字。新頁支援原圖放大、縮放拖曳、獨立初始視角、旋轉及共用編輯儲存，文字仍可從「編輯內容」調整。`assets/presentation-results.js` 載入時合併現況及成果資料，前後頁、目錄與頁數會自動更新。

## 素材待確認

提供的 PPTX 與目前 PDF 情境目錄有部分差異。例如 PPTX 有「生活副道」，目前目錄則有「平行匝道型交流道」及「路段中央分隔迴轉道」。本次沿用 `data/scenarios/catalog.json` 的固定編號與 18＋18 清單，沒有自行搬動編號。正式逐情境整合前需再對照素材。

第三期圖例討論的實際會議紀錄、逐項情境修訂前後對照，以及尚未提供的複雜情境現況照片待補。各情境最新照片及來源以 `current-conditions.json` 和素材資料夾索引為準。補充的 `01.參考指引說明會(草案)_整體簡報檔.pptx` 共 71 頁，僅第 17–19 頁為左／右錯位 T 字路口，其餘案例為一般道路情境，不移配至其他複雜情境。後續照片由使用者逐情境提供。沒有把第二期的「20 次會議」當作第三期成果，也沒有沿用草案封面的日期與人名。

## 現況素材歸檔

- `materials/04-一般道路情境/current-conditions/G1-01/` 等情境資料夾：一般情境的原始現況圖與全部照片。
- `materials/05-複雜道路情境/current-conditions/C1-01/` 等情境資料夾：複雜情境的現況圖，以及後續依提供素材補入的原始照片。未提供照片的情境維持待補，不以改善圖或其他案例代替。
- 每個情境都有 `source.json`，記錄原頁次、PPTX 媒體檔、裁切、旋轉與 SHA-256。兩個根目錄各有 `overall-presentation-index.json` 及說明文件。
- 最初擷取 106 個原始現況圖檔，包括另行歸檔的生活副道；後續 PowerPoint 與使用者附件照片持續加入，各檔均保留原始位元組及校驗碼。最新清單以 `current-conditions.json` 為準。相同原圖在數個投影片重複使用時，檔案只存一份，來源紀錄保留各頁的使用方式。
- 多張照片或代表型在各自圖框內以下拉選單、左右箭頭切換，兩框始終為「現況圖／現況照片」。切換照片不移動另一張圖的視角。每張圖的縮放、旋轉與位置仍可分別儲存。
- 左右圖片採等高填滿，維持比例並置中裁切；共用圖面元件同步對齊兩框工具列，避免照片選單造成圖片區高度不同。此方式也適用模組並排、模組子分類總覽及情境配置比較；單張圖與原圖視窗維持原呈現。既有初始畫面的設定仍以原頁面與圖片 ID 保存。
- C2-02 原未有對應素材，之後依使用者指示複用 C4-04 迴轉道的現況圖、照片與兩項議題，保留 C2-02 的編號與名稱。複本使用 C2-02 的檔名及圖片 ID，可獨立編輯，來源記錄於 `C2-02_reused-content.json`；C4-04 不變。`legacy-living-side-road` 仍保留原簡報生活副道。

`tools/extract-results-current-conditions.py <原始簡報路徑>` 可重建來源索引與原圖歸檔。原圖若已存在且內容不同會停止，避免覆寫手動調整的素材。說明文字由 `data/results/current-conditions-text.json` 提供，依原議題濃縮為簡報用語。

重建原始來源及補回 C4-04 照片後，可執行 `py -3.7 tools/reuse-current-conditions.py C2-02 C4-04 --date 2026-10-31` 重套使用者指定的現況內容複用；工具保留原始位元組與來源記錄，不改寫共用編輯設定。

重建原始資料後，再執行 `tools/supplement-complex-current-photos.py <補充簡報路徑>` 加入複雜情境照片。核對依據放在 `data/results/complex-photo-sources.json`；工具檢查 PPTX 與照片的 SHA-256、投影片頁次和情境標題，再補入照片，不替換現況圖或改寫編輯設定。補充來源記錄於清單的 `supplementalSources` 與各情境的 `photoSource`。

C1-02 的兩張原始附件另存於 `C1-02/C1-02_現況照片_01.png`、`02.png`，第一張保留上下組合構圖。`C1-02_user-photos.json` 記錄提供日期、固定 ID、尺寸與個別校驗碼。可用 `tools/import-current-photos.py C1-02` 在重建原始資料後重新套回附件照片；匯入新照片則於情境編號後列出檔案，並提供 `--date YYYY-MM-DD`。重複匯入不重複建檔，既有圖面及編輯設定不改寫。

C1-07「迷你圓環」的兩張照片依提供順序歸檔在自身資料夾，來源記錄為 `C1-07_user-photos.json`。使用者更正原先標示的 C1-06，照片與來源索引已一併移轉。之後 C1-06「街巷道多叉路口」另補入新提供的兩張照片，來源記錄為 `C1-06_user-photos.json`，兩組檔案與固定 ID 分開保存。照片框和現況圖框各自切換，選擇照片不會改變左側現況圖或其視角。
