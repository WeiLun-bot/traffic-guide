# 互動簡報視覺編輯器

## 架構與實作階段

整份教材最上層是四場簡報，載入時先顯示「四場簡報總覽」。頂部平常只顯示目前簡報名稱，例如「02 交通管制設施模組設計 ▾」，旁邊保留 00–04 章節，整合成同一列導覽。四場簡報收在名稱選單內；原有目錄仍可按簡報分組展開。前後頁、Home／End、頁碼及進度各自以當場簡報為範圍；第一頁按上一頁回總覽，最後一頁按下一頁回本場開頭。點左上品牌或名稱選單中的「四場簡報總覽」也可回總覽。

桌面滑鼠移入名稱後會展開選單，移出後收合；點擊可讓選單保持開啟，再點名稱、點選單外或按 Esc 關閉。鍵盤可在名稱按 Enter／空白或上下方向鍵開啟，使用上下方向鍵移動選項，Enter 選擇；Esc 關閉並回到名稱按鈕，Tab 可離開選單。手機使用點擊開關；名稱與章節維持同一條導覽，較長的章節列可左右滑動，當前章節會自動捲動到可見位置。選單浮在內容上方，不推擠圖片或改變圖面視角。

四場簡報為「三年成果與模組化整體架構」「交通管制設施模組設計」「一般道路情境」「複雜道路情境」。章節資料獨立放在 `data/presentations.json`；`assets/presentation-structure.js`、`.css` 管理分層導覽與尚無素材的空白頁。

模組簡報的 00 為緒論，保留功能模組架構與完整索引；01–04 依 `output_1027.pdf` 第 3 章 3.1–3.4，分別為「車道配置與動線導引」「路口管制」「行人、自行車、機車、公車」「危險警示與通行管制」。15 個模組、27 個子模組均有內容入口；其中 25 個子模組採三段式圖文解說，另兩個依 Typst 章節安排轉介至相關模組。

一般道路簡報保留原 00 緒論、01 無號誌三岔、02 號誌化三岔、03 無號誌四岔、04 號誌化四岔。緒論新增「全部情境總覽」，按 G1–G4 列出 PDF 的 18 個情境；四個已完成案例連到原頁面，其餘 14 個為空白預留頁。原「五章導覽」頁右側提供總覽入口。

複雜道路簡報的 00 緒論顯示「全部情境總覽」，按 PDF 第 5 章的四類章節列出 18 個情境：01 平面交叉、02 交流道銜接部分、03 公路與軌道系統交叉、04 路段；情境內容先留空。兩場簡報的情境及章節頁左上方都有無外框的「全部情境總覽 ↖」，回到該場簡報自己的緒論。完整名稱與章節歸屬放在 `data/scenarios/catalog.json`；`assets/presentation-scenarios.js`、`.css` 管理總覽、預留頁及返回連結。三年成果簡報暫留 00 緒論空白頁，待提供素材及細目。

既有情境與 M2-01 的頁面 ID、圖片鍵、文字鍵維持原值，原 JSON 的初始視角、文字、照片、打亮與版面覆寫可沿用。新增簡報歸屬是頁面中繼資料，不會搬移或清空原本的使用者設定。

現有 `index.html` 由 `generalRoadPresentation.navigate()` 動態渲染頁面，條文頁另有定位與放大階段。`generalRoadEditor`、`generalRoadFormatting`、`generalRoadViewport` 與 `generalRoadConditions` 分別管理內容、排版、SVG 縮放與現況對照。不可把滑鼠編輯事件直接綁在每次會被替換的元素上，也不可覆寫 SVG 的 transform 或動畫。

1. **設定與相容層**：把原 `editor-saved-data` 完整移至 `layout/presentation-layout.json` 的 `legacyState`。既有編輯器和主程式等待設定載入完成後啟動，保留原設定值、內容、動畫與 CSS。
2. **獨立編輯層**：`assets/visual-editor-core.js` 管理設定驗證、唯一 ID、復原／重做與未儲存狀態；`assets/visual-editor-io.js` 管理檔案；`assets/visual-editor.js` 與 `.css` 提供「編輯內容」內的視覺編輯工具列、選取框、拖曳、四角縮放、字體／字級與座標面板。
3. **整合與測試**：切頁完成時重新辨識元素並套用設定；更新發布清單與預覽伺服器；以單元測試及 Edge 的真實瀏覽器測試驗證。`路口管制.html` 不在這次變更範圍。

## 設定格式

`schemaVersion: 1`、`documentId: "general-road-scenarios"`、`units: "css-px"`。`legacyState` 保留既有內容與排版；`elements` 以穩定 ID 為鍵。ID 由頁面 ID、渲染階段與原編輯鍵／圖片鍵／DOM 結構路徑組成，不使用畫面文字、隨機數或當下座標。

每個元素記錄 `id`、`pageId`、`phase`、`kind`、`target`、`x`、`y`、`width`、`height`、`fontFamily`、`fontSize`、`fontWeight`、`lineHeight`。`x/y` 是相對原位置的 CSS px 位移；其他數值為 `null` 表示沿用原簡報。寬高明確設定後使用 CSS px，不將整張投影片改成絕對定位。圖片縮放改外框，原 SVG 的 viewBox、內部旋轉、發光和放大運算仍由原程式管理。

初始設定不對原版面增加任何幾何覆寫。預覽時只有右上角「編輯內容」入口；點開後可直接修改文字、使用圖片旁的「更換圖片」，並在問題與條列旁新增、排序或刪除項目。「文字樣式」統一處理字體、字級、粗細、顏色、對齊等設定；「進階版面」處理拖曳、物件尺寸、左右欄比例及間距。進階版面暫停文字輸入與打亮調整；點「返回內容編輯」繼續修改內容。右上角「完成編輯・預覽」關閉所有編輯工具，預覽投影片尺寸不變。

### 增加及管理內容

- 「現況問題」右欄底部的「＋新增現況問題」新增一組標題及說明，可按「＋新增照片」補照片，沿用原本照片與說明左右並排的版型。
- 每組現況問題下方的「＋新增說明項目」增加圓點條列。
- 條文放大解說頁的「＋新增說明項目」增加同款編號條列，編號自動接續。
- 每筆項目旁的 ↑、↓、刪除用來排序或移除；上方「復原」「重做」可還原操作。新增內容向下排列並沿用原本的捲動區域，左圖保持原設定。
- 「整體佈設策略」右欄可直接編輯策略名稱，清單下方的「＋新增佈設策略」可增加列點。每列同樣可排序、刪除、復原，編號會自動接續。
- 一般編輯時顯示共用儲存與復原工具。「設定檔」選單提供連結、重新授權、重新載入、匯出與匯入；進階版面內另保留頁面管理及舊補充區塊管理。

結構化內容存在根層 `content.conditions[pageId].issues`、`content.articles[articleId].points` 與 `content.overviews[pageId].items`。每個問題、條列及策略有固定 ID、文字鍵；排序不改 ID，照片以固定圖片鍵保存於既有 `legacyState.images`。第一次編輯時從原頁面讀取已套用的舊文字設定，後續以結構化內容為準，並同步舊文字鍵供既有樣式辨識。舊 JSON 沒有 `content` 或 `overviews` 時仍正常載入，不會自動清空或覆寫既有版面、圖面視角與打亮。文字樣式變更會清除同一物件相應的舊視覺字型覆寫，避免兩套設定互相遮蓋。

### 策略與關聯條文

在「編輯內容」模式按策略旁的「關聯條文」，可複選本情境的條文，並選擇「點整列時前往」的主要條文，也可選「不連結」。按「套用」才會記錄變更；取消或 Esc 不影響原設定。右側條號依選取的條文資料自動產生，不需手動輸入。

編輯模式點策略文字會修改內容，完成編輯後則恢復導覽：點整列會開啟主要條文，每個條號也能分別開啟對應條文。未選任何關聯條文的策略為純文字列點。設定會和其他內容一起儲存到同一份 JSON，包含 `id`、`title`、`titleKey`、`articleIds`、`targetId`；載入時會檢查條文存在且屬於正確情境。修改策略、排序、復原及調整文字樣式會保留左側比較圖當下的縮放視角與比較中線位置。

四個情境的「現況問題」頁採雙欄呈現：桌面左側約 55% 為可縮放、平移的現況圖，右側每組現況照片與問題條列採左右並排，不顯示原本的 ON SITE 標頭。左圖等比例放大填滿圖片框，超出範圍裁切；重設視圖後也會恢復填滿，可拖曳查看被裁切的部分。可拖曳的現況／配置圖對照位於各情境的「整體佈設策略」左側，右側保留策略解說。圖面對齊仍沿用原 `comparisonTransforms` 設定鍵，因此原先的位置、尺寸與旋轉不會因為移頁而遺失。

條文說明頁的左上標題依設施分類顯示為「標線條文運用解說」「標誌條文」「號誌條文」或「道路設施」，畫面不加引號。左上字級與前面的「整體佈設策略」主標題相同；右側解說大標題顯示當頁的設施主題，例如「路面邊線」「最高速限標誌」。條文編號、解說內文和圖面操作保留。

## 本機使用與儲存

### 功能模組

後續依 `05`–`15` 的 Typst 章節核對圓環並補齊其餘 10 個模組，新增 64 個主頁、79 張實際引用圖。人行穿越、號誌、機車、公車及 M4 各類管制保留條文與適用條件，文字整理為簡報用語；現況議題的新照片待提供後再加入。`M3-02.2 自行車穿越道` 連回自行車道圖例的穿越道項目，`M3-03.1 機車道` 連回慢車道銜接路口示例。

圖片只採 Typst 實際使用的 `image()` 呼叫；註解掉的圖及資料夾額外檔案不會加入。`rotation` 記錄 Typst 的旋轉方向，圖例、延伸縮圖與原圖視窗依相同方向呈現。原始圖片檔保留原樣，新增內容及既有網頁編輯覆寫仍分別存在模組 JSON 與 `layout/presentation-layout.json`。

`tools/typst-module-source.cjs` 以資料方式讀取 Typst，不執行匯入或程式碼。`tools/complete-module-presentations.cjs <Typst章節資料夾> --write` 搭配 `remaining-module-content.cjs` 產生上述 10 個模組的基本內容；不帶 `--write` 時只驗證並產出檢查紀錄。`source.imageFiles` 與 `source.sha256` 保留用圖清單及來源識別，檢查結果位於 `tests/artifacts/module-completion/`。

新增的四個模組依提供的 Typst 章節整理，共 16 個主頁、25 張原圖。每個子模組依序為「現況議題與相關條文 → 圖例說明 → 延伸應用」。現況議題頁保留條文索引與適用情境連結，點進情境後可回到原模組；單一子分類不另增一列切換按鈕。M1-02 與 M1-03 的延伸應用收錄章節中的補充圖例及實例。

M1-01.1 的現況議題頁另使用提供的兩張空拍照片，桌面預設左右並排，兩張圖可各自縮放、拖曳及開啟原圖。並排時各自顯示照片標題，省略選圖選單、切換箭頭及張數；按「單圖顯示」切回單張時，才顯示圖片選單與左右切換功能。窄螢幕則將兩張圖上下排列。此頁以 `defaultView: "pair"` 設定預設顯示方式。總覽與圖例說明繼續使用原配置圖；照片使用獨立素材 ID，初始視角不會套用舊配置圖的位置。

M1-01.2「附加車道」的現況議題頁使用提供的路口空拍照片，原檔存於 `materials/03-modules/M1-01/M1-01.2_現況議題_附加車道.png`。照片可縮放、拖曳及開啟原圖，總覽與附加車道圖例說明保留原設置圖。

M1-02.1「路徑與地點指示」的現況議題頁使用提供的街景照片，原檔存於 `materials/03-modules/M1-02/M1-02.1_現況議題_路徑與地點指示.png`。原本的錯位 T 字與渦輪圓環配置圖繼續保留在圖例說明及延伸應用素材中；現況照片使用獨立素材 ID，沿用圖片縮放、原圖及初始畫面設定功能。

M1-03.1「路側停放與裝卸車位配置」的現況議題頁使用提供的路側停車與停車格位兩張照片，原檔存於 `materials/03-modules/M1-03/M1-03.1_現況議題_路側停車.png`、`M1-03.1_現況議題_停車格位.png`。桌面預設並排，各自保留標題、縮放、拖曳及原圖功能；圖例說明沿用原配置圖。

每個模組各自儲存在 `data/modules/M1-01.json`、`M1-02.json`、`M1-03.json`、`M2-01.json`、`M2-02.json`。`catalog.json` 的 `ready` 決定載入哪些內容，發布工具只複製已宣告的 JSON 與圖片。單一模組讀取失敗時顯示該模組的重新載入提示，其餘模組仍可操作。舊預留頁網址會導向新內容，不影響原 M2-01 的 ID 與使用者設定。

M2-01 的說明採對外簡報用語：短標題直接指出重點，內文聚焦設施功能、配置位置與適用條件。尺寸與必要限制保留，文件引用集中在「資料來源」，不在講解內文穿插編寫或素材整理過程。原有頁面、說明項目及圖面定位 ID 沿用，因此編輯與版面設定仍可繼續使用。

啟動本機預覽後，選「交通管制設施模組設計」。00 緒論以整個內容寬度呈現四大主題、15 個模組及 27 個子模組的架構與主題卡片；可點選卡片或上方章節進入各類模組，頁尾下一頁可開啟全部模組總覽。各模組均已接上圖文內容或原章節指定的相關說明入口。

模組主題頁移除與頂部章節重複的「全部模組、M1–M4」篩選列；主題切換統一使用頂部 01–04。00 緒論保留架構介紹，並以「全部模組總覽」按 M1–M4 分組展示全部 15 個模組。各主題、模組與子分類頁左上方的「全部模組總覽 ↖」都回到這份總覽。

使用頁面左下角的「全螢幕」按鈕後，桌面寬度的 M1–M4 主題頁會套用較緊湊的排列：「全部模組總覽 ↖」保留在標題上方獨立一行，並適度縮小卡片內距、最小高度及上下間距。原本三欄／兩欄排列、標題與內文字級保留。一般視窗、窄螢幕或開啟「編輯內容」時沿用原排版；退出全螢幕即恢復。這是暫時的呈現樣式，不會改寫已儲存的版面 JSON，也不會裁切超出畫面的內容。此階段只處理 M1–M4 主題頁，全部模組總覽及長篇解說維持原本閱讀方式。

所有模組內容頁共用同一列導覽：左側保留「全部模組總覽 ↖」，以模組下拉選單切換同章模組，旁邊直接顯示子分類。例如 M2-01 可選「總覽」「M2-01.1 停管制」「M2-01.2 讓管制」。子分類超過三個或一列放不下時，改用子分類下拉選單；窄螢幕自然排列成兩列。切換模組與子分類不會改寫版面設定。

選擇子模組後先開啟「現況議題與相關條文」；「總覽」下保留模組總覽與情境應用。只有一個子分類時，省略子分類選擇，直接以子分類編號及名稱作為內容標題；尚無素材的分類保留空白頁。

模組總覽依子模組分組，每個子模組各占一個圖框，桌面預設全部並排，窄螢幕自然換行。例如 M1-01 固定呈現「M1-01.1 路口與路段車道配置」及「M1-01.2 附加車道」兩框；M4-01 的局部危險警示與路段危險警示各一框。每框預設以該子模組「現況議題」的代表型清單為準，同一子模組有多張代表型時，才提供框內下拉選單、上一張／下一張及張數，切換不影響其他子模組。

總覽可在模組 JSON 第一頁的 `overviewGroups` 按子模組 ID 設定 `label`、`hidden`、`sourceModuleId` 與 `assets`，以合併圖框或共用其他模組的圖例。自行車總覽合併成「M3-02.1 自行車道、M3-02.2 自行車穿越道」一框，穿越道的子分類及原說明入口仍保留。機車道總覽引用 M1-01 的一般寬度與窄慢車道兩張圖，提供同樣的切換、縮放、拖曳、原圖及初始畫面設定；共用原圖檔及素材 ID，各總覽仍各自保存初始視角。未指定共用圖的轉介子模組保留說明入口。

總覽右側統一標為「模組說明」，原始列點只介紹各子模組，標題統一顯示「子模組編號＋名稱」。已移除原本額外的「先確認車道連續性」「建立主次路權」「配置重點」。每項的 `submoduleId` 對應固定編號，原有說明 ID、文字及字體設定延用；即使舊 JSON 還存有已移除的原始列點，也依總覽的 `excludedOverviewPointIds` 排除，不改寫原設定檔。自行修改的文字及新增說明仍可編輯與儲存。有實際條號的總覽在說明列點下方保留相關條文按鈕；子模組現況議題的相關條文索引維持原功能。

子模組內容頁一次顯示一張代表型；多張圖在圖片框上緣切換，仍可使用「並排比較」及「單圖顯示」。每張圖原本的圖片 ID、初始旋轉、縮放及位置各自保留，總覽圖面繼續使用原總覽頁 ID 儲存。圖片框下方不再顯示圖名、來源或操作提示列，延伸應用附圖也移除下方圖名；原圖按鈕及附圖點選放大繼續保留。資料來源仍可由說明區的「資料來源」查看。

模組標題與代碼使用較緊湊的排列，圖文欄位約為 2：1，圖片框使用扣除導覽、標題及底部項目後的剩餘高度。右側「適用情境」預設收合，展開後仍能跳到情境並返回原模組。這些呈現調整不會重寫已儲存的版面 JSON。

M2-01 呈現為 8 個主頁：總覽及情境應用各一頁，停管制與讓管制各三頁。頁尾前後頁及鍵盤方向鍵依序走「現況議題與相關條文 → 圖例說明 → 延伸應用」。現況議題與相關條文頁左側放代表圖、右側列出原稿議題，相關條文移至左右欄下方，沿用一般情境的條文索引按鈕，完整顯示「§條號＋名稱」，可點選查看原有配置說明；條文名稱記錄於模組 JSON 的 `referenceNames`。相關條文集中於首個主題頁底部；圖例說明採左圖右文，下方小按鈕切換說明與打亮位置，停管制有四項、讓管制有三項。延伸應用則將各自四個項目整合在一張簡報，以四個說明框呈現；一般桌面視窗採兩欄、四框排列；全螢幕且寬度超過 900 px 時，一次顯示兩個較高的說明框並加大附圖，以「上一組／下一組」、頁尾前後頁或方向鍵切換第 1–2／3–4 項，看完最後一組才前往下個主題。退出全螢幕、窄螢幕或進入編輯時會呈現全部項目；較長文字可在框內捲動，編輯時展開完整內容。有對應素材才附圖，可點選縮圖查看原圖；路口預告標誌採純文字，保留完整說明。

流程與按鈕對應記錄於 `data/modules/M2-01.json` 的 `submoduleFlows`，12 份原始圖文仍保留原 ID。合併進延伸應用的舊網址（例如 `#m201-stop-crosswalk`、`#m201-yield-buffer`）會開啟該子模組的延伸應用整合頁。圖例說明網址包含 `/topic-項目ID`，重新整理後保留選取；延伸應用只需單一頁面網址。各項的文字、圖片、初始視角與打亮繼續使用原圖文 ID 儲存。新增說明另記錄 `topicId`，只出現在對應主題或說明框；同一份原始圖文裡的其他主題不受新增、刪除及排序影響。

延伸應用會依圖檔旋轉後的寬高比例選擇預設版型：附圖皆為寬度至少兩倍高度的長圖時，採「上文字、下圖片」，圖片使用說明框的完整寬度；其餘維持左右排列。沒有附圖的框維持純文字。全螢幕仍一次顯示兩個說明框，較長文字可在框內捲動；窄螢幕改用適合閱讀的上下排列。

按「編輯內容」，各有圖說明框的標題旁會出現「圖文排列」選單，可選「自動（上下／左右）」「左右排列」「上下排列」。每框分別設定，切換保留原標題、條列及圖片，支援復原／重做，按共用的「儲存」即可在重新整理後沿用。選回「自動」會移除該框的手動指定。設定保存在正式 JSON 根層的 `extensionLayouts`，以「延伸應用頁 ID／項目 ID」為鍵；舊設定缺少此欄位時直接使用自動版型，不改寫原檔。

若整個子模組不需要延伸應用，在該頁按「編輯內容 → 刪除整頁延伸應用」，會回到同一子模組的「圖例說明」。目錄、頁碼、段落總數與前後頁會同步略過已刪除頁；例如三段流程改顯示為兩段。按「儲存」保留刪除狀態，支援復原／重做。需要補回時，在同一子模組的現況議題或圖例說明頁進入編輯，按「恢復延伸應用頁」。原本的卡片、文字、圖片、圖文排列與版面設定均會恢復。

已移除頁面的固定 ID 存在根層 `removedModuleExtensions`，原模組 JSON 與素材檔案保留。各子模組可分別決定是否保留延伸應用；舊設定沒有此欄位時全部照常顯示。重新開啟已刪除頁的舊網址或舊卡片連結，會前往該子模組的圖例說明，不會出現空白頁。

- 圖例說明與現況圖可滾輪縮放、拖曳，按「原圖」查看完整素材；延伸應用的附圖可點選放大。
- 現況圖及圖例說明的「設定初始畫面」每頁、每圖分別儲存。延伸應用改用附圖縮圖，原有視角設定仍保留於 JSON。
- 按「編輯內容」可修改解說標題及內文，新增、排序、刪除說明，調整文字樣式、更換圖片與調整打亮。儲存仍使用同一份 `layout/presentation-layout.json`，不必另外儲存每個模組。
- 各情境「整體佈設策略」的 M2-01 標籤可開啟模組。「情境應用」中已製作的案例可前往整體佈設策略，再按「返回 M2-01」。

### 模組圖例的打亮框

「圖例說明」可點選下方主題或右側說明項目，顯示對應的琥珀色打亮框；點右側項目會放大到該位置。沒有設定打亮框的說明維持完整圖面。M1-01 的路口配置、附加車道與原有 M2-01 圖例已提供預設位置，其餘圖例可自行新增。

按「編輯內容 → 調整打亮」，在圖片上方選擇要調整的說明項目。沒有框時按「新增打亮框」，再拖曳框身移動、拖曳四角改大小，或直接修改左、上、寬、高。選「放大範圍」可調整點選說明後的取景範圍；圖片原本的旋轉與「設定初始畫面」的旋轉都可沿用。

不需要的框可按「刪除打亮框」，原位置仍會保留，之後可按「恢復打亮框」。新增、調整、刪除與恢復均支援復原／重做。每筆說明與每張代表型各自儲存框選，不影響同主題的其他圖片。新增的說明項目也可設定自己的框。完成後按共用的「儲存」，框選與刪除狀態都存入同一份 `layout/presentation-layout.json`，重新整理仍會保留。

### 拖曳排列圖例與條文按鈕

按「編輯內容」後，模組「圖例說明」下方的主題按鈕、道路情境下方的條文索引會出現拖曳提示。按住按鈕拖至目標按鈕左側或右側，看到琥珀色放置標記後放開，即可調整順序；換行時也可跨列拖曳。按 Esc 或放到按鈕列外可取消，不會留下修改紀錄。也可將鍵盤焦點移到按鈕，以 Alt＋←／→調整順序。正常點擊仍可切換說明，完成編輯後恢復原本的預覽操作。

模組順序依各子模組的圖例說明頁分開保存；條文順序依各情境分開保存，並同步到目錄、解說序號及前後頁。行穿線的配置比較頁會跟隨相關條文。重新排序保持目前選取的主題／條文、說明內容、打亮與圖面視角；支援復原、重做及共用 JSON 儲存。複雜道路情境沿用同一條文元件，補入條文素材後即可使用；目前留空的情境不另產生條文按鈕。

順序記錄於正式 JSON 的根層 `navigationOrders`，以 `module:圖例說明頁ID` 或 `scenario:情境ID` 為鍵，值為固定項目 ID 的陣列。舊設定沒有這個欄位時沿用原順序；後續新增的項目接在已排序項目後，已移除的 ID 不影響其他內容。共用的 `assets/presentation-order.js`、`.css` 處理排序及拖曳操作。

模組架構原始資料為 `data/modules/catalog.json`，M2-01 原始圖文為 `data/modules/M2-01.json`，8 張原素材放在 `materials/03-modules/M2-01/`。網頁編輯後的覆寫放在 `content.modules[pageId].points`、`legacyState`、`elements` 及 `imageViews`；舊設定沒有 `modules` 欄位也可正常載入。排序保留說明 ID、文字樣式及圖面定位關係。

內容依提供的 `output_1027.pdf` 正文第 3–5、46–51 頁整理。圖例保留原圖；讓管制搭配行穿線的提供圖屬下游空間不足的配置，頁面有單獨說明。讓管制的庇護與路緣頁借用停管制圖說明空間概念，並明確註記。每頁「資料來源」可查看引用範圍及視距檢核依據。

在專案資料夾雙擊 `start-editor.cmd`，再用 Chrome／Edge 開啟視窗顯示的 localhost 網址。使用期間保持該視窗開啟；結束時按 Ctrl+C 停止預覽。啟動檔會自行定位專案，不必先在 PowerShell 切換資料夾。

也可以在專案根目錄的 PowerShell 執行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\preview-editor.ps1`。啟動腳本採用 ASCII，避免 Windows PowerShell 5.1（含 x86）誤讀無 BOM 的 UTF-8 中文字串。本機伺服器的 HTML／資源來自 `_site`，但 `layout/presentation-layout.json` 每次都讀取專案根目錄的正式設定，不使用 `_site/layout` 的舊副本。因此儲存正式 JSON 後，重新整理就能讀回最新設定，不需要重建預覽或依賴瀏覽器保留的檔案授權。JSON 寫入仍透過瀏覽器授權，伺服器只接受讀取。

請儲存至 `traffic-guide/layout/presentation-layout.json`，而非 `_site/layout/presentation-layout.json`。更新預覽伺服器程式後，需關閉原先的預覽視窗，再重新雙擊 `start-editor.cmd` 一次。對外發布仍須重新產生 `_site` 並上傳，才會包含最新 JSON。

點右上角「編輯內容」，再開啟「設定檔 → 連結設定檔」，選擇本機 Git 專案的 `layout/presentation-layout.json`。之後「儲存」或 Ctrl/Cmd+S 會寫回同一個檔案，不會每次下載。瀏覽器可能在重新開啟後要求再次授權；檔案控制代碼保存在該瀏覽器的 IndexedDB，不會放進公開設定。File System Access API 需要安全來源（localhost 或 HTTPS）和使用者操作。

### 現況圖的初始畫面

情境開場頁、「現況問題」及模組圖面都有「設定初始畫面」按鈕。開啟後可調整初始縮放百分比、左右位置、上下位置與旋轉角度；位置正值分別向右、向下移動，角度正值順時針旋轉。可直接輸入 -360°～360°，或使用「左轉 90°／右轉 90°」。旋轉後仍可在圖上使用滾輪及拖曳，再按「套用目前畫面」。

按「儲存設定」會使用同一套 JSON 直接寫檔／匯出流程；面板開啟時也可按 Ctrl/Cmd+S。這兩頁各自保存設定，切頁後重新進入、重新開啟及按圖上的「重設視圖」都會回到已設定的畫面。「回到原始畫面」則恢復程式預設，之後仍需儲存。可用復原／重做還原調整。

設定位於 `imageViews`，以頁面與素材 ID 識別，保存 `zoom`、`x`、`y`、`rotation`（度）；100% 縮放代表旋轉後的原始視角範圍，左右／上下位移分別以目前縮放視窗的寬／高為百分比基準。各頁、各圖的設定彼此獨立，舊版沒有 `imageViews` 或 `rotation` 的 JSON 仍可匯入；未設定旋轉時使用 0°，保留圖檔本身的方向。一般預覽時的縮放、拖曳不會自動覆寫初始設定。

其他瀏覽器使用「匯入 JSON」與「匯出 JSON」。以檔案網址直接開啟 HTML 時，瀏覽器可能封鎖 JSON 的 fetch；此時畫面會提示匯入設定後啟動，不會悄悄套用空白設定。設定讀取、驗證、權限或寫入失敗時均保留目前未儲存內容。

儲存前會重新讀取已連結檔案，若外部編輯器／Git 改過內容就停止寫入，請先匯出自己的版本，再重新載入合併。拖曳結束才產生一筆復原紀錄；Esc／pointercancel 取消拖曳。Ctrl/Cmd+Z 復原，Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做，方向鍵移動選取元素（Shift 為 10 px）。

設定檔只含簡報設定，不需要 GitHub Token、GitHub API 或後端寫檔服務。舊內容編輯器的變更也會在 JSON 儲存時納入 `legacyState`；JSON 是載入時的正式設定，舊 localStorage 草稿不會蓋過它。舊內容工具列的「下載 HTML」已接到相同的 JSON 儲存流程並改名「儲存 JSON 設定」，兩種編輯模式都支援 Ctrl/Cmd+S。

舊圖面放大版產生工具會讀取外部 JSON，為產出的 HTML 另建 `.layout.json` 副本，不修改正式設定。瀏覽器記住的檔案控制代碼依設定路徑區分，避免不同副本互相套用。

## 檔案與驗證

- `index.html`：外部資源、設定就緒等待、切頁套用與鍵盤事件接點。首次開啟或重新整理時，會先顯示載入提示，等設定、四場簡報導覽與指定頁面建立後才顯示簡報，避免短暫出現舊章節列。設定讀取失敗時可在提示中匯入 JSON；程式載入失敗時可重新載入。
- `layout/presentation-layout.json`：唯一正式版面設定。
- `assets/visual-editor-core.js`、`visual-editor-io.js`、`visual-editor.js`、`visual-editor.css`：編輯器。
- `assets/initial-image-view.js`：兩頁現況圖的初始視角控制與還原。
- `assets/structured-content.js`：現況問題、問題條列、條文條列的結構化編輯及共用工具介面。
- `tools/prepare-github-pages.cjs`、`serve-github-pages.cjs`、`preview-editor.ps1`：發布與本機預覽。
- `tests/verify-github-pages.cjs`、`visual-editor.test.cjs`、`visual-editor-browser.cjs`：發布、狀態／檔案與瀏覽器回歸驗證。

API 依據：[Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[MDN createWritable](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)。


只有 VS Code 時，`tools/preview-editor.ps1` 已包含 Node 執行環境的替代方式。瀏覽器測試需要已安裝的 Edge／Chrome，可用 `VISUAL_EDITOR_BROWSER` 指定執行檔。測試會使用獨立且隱藏的瀏覽器設定目錄，結束後關閉；測試結果和截圖位於 `tests/artifacts/visual-editor/`，不會發佈。

單元測試檢查狀態、輸入驗證、檔案衝突、舊工具相容性、初始圖面視角與對照功能移頁。Edge 測試涵蓋真實滑鼠與鍵盤、保存與重新載入、舊內容編輯器、兩頁獨立的初始圖面、四個情境的拖曳對照，以及桌面與手機版面。未調整頁面的版面比對使用安裝前的 `baseline.html` 暫存副本；若副本不存在，測試報告會明確註記未執行幾何比對，原程式區塊的雜湊驗證仍可由單元測試執行。

真正的 `FileSystemFileHandle.createWritable()` 和 IndexedDB 還原已用瀏覽器私有的測試檔驗證；拒絕權限與衝突流程另用模擬控制代碼測試。OS 選檔對話框與本機專案檔案的寫入授權仍需使用者實際操作確認。`--artifacts-only` 不驗證 GitHub workflow；本專案目前未包含該 workflow。
