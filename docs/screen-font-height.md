# 固定文字占畫面高度

字型及基準字級採用 GitHub `a3ebef3` 的同事設定，包含 `assets/presentation-reading.css` 與 `layout/presentation-layout.json` 的個別物件設定。本機的一般道路用語、DOCX 內容、條文分類、條文編號白邊外的黑色外框及預覽啟動修正一併保留。

左下角「版面」及精簡導覽切換已撤回；舊的瀏覽器版面偏好不再影響閱讀畫面。

頁首頁尾另以 **1920×1080、Windows 100%、瀏覽器 100%** 為基準，各為 50 px，固定占螢幕高度約 4.63%。按鈕為 40 px，上下各留約 5 px（含分隔線）；頁首導覽、頁碼、總頁數、步驟與頁尾標籤等文字統一為 14 px。可編輯環境中，編輯按鈕放在目錄按鈕右側；純瀏覽環境隱藏編輯按鈕，目錄按鈕靠最右側。鍵盤焦點順序與畫面順序一致，手機亦採相同按鈕順序。

倍率為 `screen.height ÷ 1080`；1920×1080／125% 時，頁首頁尾各為 40 CSS px、按鈕 32 CSS px、留白各約 4 CSS px、文字 11.2 CSS px。經 Windows 放大後，占螢幕比例與 100% 相同。相較上一版各 78 px 的頁首頁尾，現在合計多出 56 個實體像素高度給內容。

頁首頁尾的文字、圖示、按鈕及間距一起使用 CSS `zoom` 換算，並同步更新主內容預留高度，避免只縮外框卻留下空白或讓按鈕突出；[CSS zoom 會參與版面配置](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/zoom)。手機及 620 px 以下的窄視窗維持原本兩列導覽方式。此倍率與下面的內容字級倍率分開，符合兩者指定的不同參考環境。

編輯時的儲存／狀態訊息顯示於頁尾上方，保留 14 px 基準字級及完整訊息的滑鼠提示，不再新增第二列擠壓頁尾按鈕。

依最新指定，顯示基準改成 **1920×1080、Windows 125%、瀏覽器 100%**，螢幕邏輯高度為 `1080 ÷ 1.25 = 864` CSS px。閱讀與編輯預覽共用以下換算：

```text
顯示字級 = 儲存的基準字級 × screen.height ÷ 864
```

`screen.height` 是作業系統縮放後的螢幕邏輯高度，不需要猜測 Windows 的縮放百分比或直接反乘 `devicePixelRatio`。因此相同實體解析度在 Windows 100% 與 125% 下，字級框占螢幕高度的比例相同。一般視窗、編輯面板、瀏覽器工具列與全螢幕切換都不再改變這個比例。

| 螢幕解析度 | Windows 比例 | 螢幕邏輯高度 | 基準 24 px 的顯示字級 | 基準 16 px 的顯示字級 |
| --- | --- | --- | --- | --- |
| 1920×1080 | 125% | 864 | 24 px | 16 px |
| 1920×1080 | 100% | 1080 | 30 px | 20 px |
| 3072×1920 | 200% | 960 | 26.67 px | 17.78 px |
| 3084×2160 | 300% | 720 | 20 px | 13.33 px |
| 2560×1600 | 175% | 約 914.29 | 約 25.40 px | 約 16.93 px |

以上以瀏覽器 100% 計算。24 px 與 16 px 分別占全螢幕高度約 2.78% 與 1.85%。這是同字型字級框的占比，實際字形高度還取決於字型。最新基準與原先附圖的 2560×1600／175% 基準不同，因此該環境下現在也會相應換算。

同事已儲存的每一筆字級仍是基準值，不把所有字級改成單一值，也不改寫 JSON。個別物件的 inline `!important` 字級會一起換算。編輯面板標示「基準字級 px」，例如顯示畫面為 20 px 時，欄位仍顯示及儲存 16 px，避免換電腦或反覆編輯造成累積縮放。

參考字型規則按基準視窗的媒體條件與 viewport 單位計算，避免換螢幕後部分標題因 `vw`、`clamp()` 或斷點而改變字級占比。行高與網頁產生的編號文字一起換算。長頁面、文字區及表格沿用同事版本的捲動方式，不以整頁縮放再次縮小文字。

列印與 PDF 匯出使用原始基準字級。圖面內的 SVG 文字、照片及內嵌文件維持各自圖面或文件的顯示方式；此功能處理桌面網頁內容文字，手機保留原本閱讀方式。

瀏覽器的 Ctrl＋滾輪或 Ctrl＋加減保留使用者主動縮放的作用；放大後文字的螢幕占比會增加。跨電腦比較時請先用 Ctrl＋0 回到 100%。不使用 `devicePixelRatio` 猜測並抵銷瀏覽器縮放，因為它同時受螢幕像素比例與網頁縮放影響。[MDN 說明](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)。

驗證命令：

```text
node tests/visual-editor-browser.cjs --font-height-only
```

驗證新基準保留同事儲存字級，並比較 3072×1920／200%、3084×2160／300%、1920×1080／100%、1920×1080／125%、2560×1600／175%。另逐項檢查範例「設置要點」與內文在閱讀、編輯、不同視窗高度下的精確 24／16 與 30／20 px、行距 1.4、個別 `!important` 設定、修改及換頁後不累積縮放、列印還原基準、下載 HTML 清理執行期樣式、撤回版面切換、黑色條文外框及長目錄捲動。顯示配置使用等效 CSS 視窗及 DPI 模擬，全螢幕透過實際 Fullscreen API 驗證；沒有實際切換本機 Windows 顯示設定。

頁首頁尾另驗證各顯示配置的高度占比、填滿視窗寬度、主內容使用剩餘高度、外層頁面不因導覽而溢出，以及按鈕均在導覽列內。用實際滑鼠座標點擊縮放後的簡報選單與操作說明，並檢查手機的 108 px 雙列頁首與 65 px 頁尾維持原設定。100%／125% 的閱讀畫面截圖與量測資料保留在 `tests/artifacts/screen-chrome-height/`。
